# Agent Note: 错选项账本、同组辨析和旧笔记对质

Status: implemented

## Problem

交卷只留下每题最新的对错。看不出同一个错字母被选过几次，旁边也没有题库里该选项自己的解释。选项名相同的题不会收成一组。费曼笔记再次保存会盖住上一次原文，同一空再次答错时没有当时写下的句子可对。

## Decision

`attempt_log` 只追加。每次交卷按空写一行：用户、题库、题目、空号、选项字母或空值、对错、时刻。`study_record.attempt` 仍是该题最新逐空结果，错题筛选继续读它。交卷不调用完成复习。

错选项按题汇总在 `packages/desk`：同一个空、同一个错字母计次数，并带上题库里该选项的名称、「是什么」和「为什么错」。未揭晓的空不显示这段，避免在遮挡时漏出解释。静态页把同一形状的流水放在 `localStorage` 键 `architecture_review_attempt_log_v1`。

同组题目由选项名在运行时求出，不往题库加字段。名称相交的题收进与「开始自测」相同的焦点队列，队列里包含当前题。未答不进入这个队列，答错才进入。交卷仍走原来的路径，不改 `nextReviewOn`、阶段或复习次数。见 [交卷队列、错题、草稿和月历](./2026-11-01-exam-queue-shared-desk.md)。

`note_history` 只追加。费曼三段与库中文本不同，且去掉空白后仍有字，才写入这次原文和时刻。空文本和未改的文本不追加。同一空的最新一行是答错，并且更早还有一次答错，才在正确选项的「为什么对」旁写上更早那次非空笔记和日期。没有这样的笔记时不显示。笔记原文不改写。静态页用 `architecture_review_note_history_v1`。

`notesChanged` 与 `hasNoteText` 在 `@atlas/domain` 和 `@atlas/desk` 各有一份，`tests/startup.mjs` 锁住两边，和 `hasWrongBlank` 同一做法。静态页不引用 `@atlas/domain`。

账本带题库列，因为学习记录按用户和题库分开。这是现有记录的范围，不是另一套间隔。

## Alternatives considered

把历次选择叠进 `study_record.attempt`。最新对错会被冲掉，错题筛选和追加流水会抢同一列。

把同组编号写进题库。题面是只读的，选项名已经能算出这些题。短名字也会对上，例如数字选项。不另做一份停用词，停用词会变成第二份手写索引。

用模型给旧笔记打分或改写。产品不要批改。旁边只引用原文和日期。

给同组单独做间隔和复习次数。那是第二台复习机器。队列复用交卷，完成复习仍是唯一推进间隔的入口。

## Consequences

`packages/bank-architecture` 和 `src/data.js` 没有改。等级、间隔天数和笔记长度仍由原来的规则计算。导入本机旧记录不写这两份流水。

`packages/desk` 的测试覆盖账本、同组和旧笔记出现的条件。`packages/domain` 的测试覆盖笔记变化和字母与对错成对，并确认它们不推进间隔。`tests/startup.mjs` 覆盖静态页的追加、再次答错后的原文，以及同组队列不增加复习次数。API 测试在已有 `study_record` 的库上应用迁移，再确认追加、不覆盖，以及完成复习仍单独推进间隔。
